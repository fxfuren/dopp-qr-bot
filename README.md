# DOPP QR Bot

Telegram бот для работы с PDF-документами ДОПП. Работает в двух режимах: помогает водителям найти QR-код по номеру СМР или авто, и автоматически загружает PDF из группового чата на Яндекс Диск в нужную папку.

## Возможности

### Личный чат (водитель → бот)
- Поиск QR-кода по **номеру спецификации** (СМР): `47589`, `47589/1`, `AVN2218`
- Поиск QR-кода по **номеру автомобиля**: `P768CA40`, `C542OA67`
- При поиске по авто — возвращает **все документы за последние 30 дней** (одна машина может иметь несколько рейсов)
- Уведомления в группу при каждом успешном запросе QR-кода

### Групповой чат (загрузка документов)
- Бот ловит PDF-файлы, отправленные в группу
- Извлекает из PDF поля «Организация» (1А) и «Поставщик» (2А)
- Fuzzy-матчит значения против папок верхнего уровня на Яндекс Диске
- Загружает файл в найденную папку (или в корень если не нашёл)
- Отвечает в чат с результатом
- Индексирует документ в кэш для будущих поисков

### Кэш (SQLite)
- Хранит извлечённый текст, номера СМР, номера авто/прицепа для каждого PDF
- Повторные запросы не скачивают файл с Яндекс Диска — берут из кэша
- Поиск по авто за 30 дней работает полностью из кэша

## Требования

- Docker и Docker Compose
- Telegram Bot Token (получить у [@BotFather](https://t.me/BotFather))
- Yandex Disk OAuth Token (получить на [oauth.yandex.ru](https://oauth.yandex.ru/))
- Бот должен быть **добавлен в группу** с правами на чтение сообщений и отправку ответов

## Быстрый старт

### 1. Клонирование репозитория

```bash
git clone https://github.com/fxfuren/dopp-qr-bot
cd dopp-qr-bot
```

### 2. Настройка окружения

```bash
cp .env.example .env
```

Отредактируйте `.env`:

```env
BOT_TOKEN=your_telegram_bot_token
YANDEX_DISK_TOKEN=your_yandex_disk_token

# Корневая папка на Яндекс Диске (папки организаций — прямые подпапки этой)
YADISK_FOLDER=/СПОТ

# Опционально: ID группового чата для уведомлений о QR-запросах
# NOTIFICATION_CHAT_ID=-1001234567890

TMP_DIR=/tmp/dopp_bot
DATA_DIR=./data
QR_DPI=350
LOG_LEVEL=INFO
```

### 3. Запуск

```bash
docker compose up -d

# Проверка статуса
docker inspect dopp-qr-bot --format='{{.State.Health.Status}}'

# Логи
docker compose logs -f
```

## Использование

### Поиск QR-кода (личный чат)

1. Отправьте боту номер СМР или номер авто
2. Выберите тип поиска кнопкой:
   - **По номеру СМР** — ищет файл где упоминается этот номер спецификации
   - **По номеру авто** — ищет все документы с этим авто за последние 30 дней
3. Бот отправит QR-код(ы) из найденных PDF

Примеры запросов:
```
47589        → все документы с номером 47589, 47589/1, 47589/2 и т.д.
47589/1      → только документ с номером 47589/1
AVN2218      → документ с буквенным номером
P768CA40     → все рейсы этого авто за 30 дней
```

### Загрузка PDF в группе

Отправьте PDF-файл в группу где состоит бот. Бот:
1. Извлечёт из документа название организации (поле 1А) и поставщика (поле 2А)
2. Найдёт подходящую папку на Яндекс Диске (нечёткое совпадение, порог 75%)
3. Загрузит файл и ответит:

```
✅ Файл 48715.pdf загружен в папку Элкомэлектро.
Совпадение по: организация
```

Если папка не найдена — файл загружается в корень (`YADISK_FOLDER`) с предупреждением.

Если два поля указывают на разные папки — бот отказывает в загрузке и просит загрузить вручную.

## Структура Яндекс Диска

Бот ожидает следующую структуру:

```
/СПОТ/                     ← YADISK_FOLDER
├── Элкомэлектро/          ← папки организаций (верхний уровень)
│   ├── 48715.pdf
│   └── 47589.pdf
├── ДругаяОрг/
│   └── AVN4128.pdf
└── 48715_неопознан.pdf    ← файлы загруженные в корень (папка не найдена)
```

Названия папок матчатся fuzzy-алгоритмом — точное совпадение не требуется.

## Настройка уведомлений

Когда водитель получает QR-код, в чат `NOTIFICATION_CHAT_ID` приходит уведомление:

```
Водитель запросил QR-код и успешно его получил

👤 Водитель: @username
📄 СМР: 47589
🚗 АВТО: P768CA40
🚛 ПРИЦЕП: 25ALW05KZ
```

Получить Chat ID группы:
1. Добавьте бота [@getidsbot](https://t.me/getidsbot) в чат
2. Отправьте `/start@getidsbot`
3. Скопируйте ID (начинается с `-100`)

## Production

### Безопасность
- Non-root пользователь (UID 1000)
- Read-only filesystem
- No new privileges
- Minimal base image (python:3.13-slim)
- Multi-stage build

### Надёжность
- Healthcheck с проверкой PID и heartbeat файла
- Graceful shutdown (SIGTERM/SIGINT)
- Restart policy: unless-stopped
- Init system (tini)
- Ротация логов: 7 дней, сжатие zip
